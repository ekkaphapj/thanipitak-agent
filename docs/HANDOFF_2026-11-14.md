### ลำดับการสั่งงานผ่านเทอร์มินัลแผง (login API → websocket)

ปุ่ม/การพิมพ์ในหน้าเว็บแผงผ่าน automation ไม่เสถียร ใช้ websocket ของเทอร์มินัลตรง ๆ แทน (สคริปต์อยู่ใน repo ชื่อ `deploy_via_panel.mjs`):

1. login ให้ได้ csrf + cookie (ต้องมี header Origin/Referer ไม่งั้นได้ "คำขอไม่ถูกต้อง"):
   ```bash
   curl -sc jar -H "Origin: https://server.policeshield4.com" \
     -H "Referer: https://server.policeshield4.com/" -H "Content-Type: application/json" \
     --data-raw '{"username":"<user>","password":"<pw>"}' \
     https://server.policeshield4.com/api/login        # → {"csrf": "..."}
   COOKIE=$(grep -i session jar | awk '{print $6"="$7}' | paste -sd";")
   ```
2. รันคำสั่งบนเซิร์ฟเวอร์: `node deploy_via_panel.mjs <csrf> "$COOKIE" '<command>'`
   - สคริปต์รอ marker `D0NE-RC=<n>` แล้วพิมพ์ output (strip ANSI แล้ว)
   - **timeout ~150 วินาทีต่อคำสั่ง** — งานนาน (apt/pip/โหลดโมเดล/เทสต์ชุดใหญ่) ต้อง `nohup ... >/tmp/x.log 2>&1 &` แล้ว poll `cat /tmp/x.log` ทีละรอบ
   - ส่งไฟล์ config ขึ้นเซิร์ฟเวอร์ใช้ base64 เลี่ยงปัญหา quoting
3. deploy จริงตามลำดับ: `cd ~/thanipitak-agent && git pull origin main` → รันเทสต์ → restart บริการ:
   ```bash
   printf '<sudo pw>\n' | sudo -S -p '' systemctl restart qwen-draw@ekkaphap && systemctl is-active qwen-draw@ekkaphap
   ```

### ฟีเจอร์: เผยแพร่โค้ด HTML จากแชตเป็นหน้าเว็บจริงบนเซิร์ฟเวอร์

**ความต้องการของผู้ใช้:** เวลาสั่ง AI เขียนเว็บในแชต ให้ระบบสร้างไฟล์ html จริงบนเซิร์ฟเวอร์ + ถ้ามีรูปที่อัปโหลดมาให้สร้างโฟลเดอร์เก็บไฟล์พวกนั้นแล้วให้ลิงก์เปิดเลย (มาจากภาพตัวอย่าง: แนบโลโก้ → ขอ HTML dashboard → ได้แต่ code block กดคัดลอกได้อย่างเดียว)

**ฝั่งเซิร์ฟเวอร์ (`draw_server.py`)**

- ตารางใหม่ `sites(id, user_id, name, dir, key, bytes, created_at)` (draw_server.py:266) — `init_db()` สร้างเองตอน restart ด้วย `CREATE TABLE IF NOT EXISTS` **ไม่ต้อง migrate มือ**
- `POST /api/sites` (handler :2656, ตัวสร้าง `create_site()` :624) — body `{name?, html?, files?: [{name, data(base64)}]}`:
  - สร้างโฟลเดอร์จริง `user_data/users/<username>/sites/<id 12 hex>/` เก็บ `index.html` + ไฟล์ asset ที่ส่งมา
  - ถ้าไม่มี html แต่มี files → สร้างหน้าแกลเลอรีไทยอัตโนมัติ (`site_gallery_index()` :589) — ใช้กับปุ่ม 🔗 "สร้างลิงก์ไฟล์" ของรูปแนบ
  - คืน `{ok, id, name, url: "/s/<id>/<key>/", bytes, storage}` — **ไม่มี field key ใน response**
  - จำกัด: html ≤ 2MB, ไฟล์ ≤ 12 ไฟล์/15MB ต่อไฟล์, body ≤ 40MB, นับรวมเข้าโควตา 50MB ของ user (ตาราง sites เพิ่มใน `used_bytes()` และ `storage_summary()` เป็น `sites_bytes`/`site_count`)
- `GET /s/<id>/<key>/` และ `/s/<id>/<key>/<ไฟล์>` (:2488, `_serve_site()` :2630) — **เปิดได้ไม่ต้อง login** (key สุ่ม 16 hex คือประตูเข้า ตั้งใจให้แชร์ลิงก์ต่อได้)
  - กัน path traversal: unquote แล้วยืนยันชื่อผ่าน `SITE_NAME_RE` (A-Za-z0-9._- ยาว 1-80, ห้ามขึ้นต้นจุด) + `resolve()` + prefix check + ห้าม subdirectory
  - Content-Type ของรูปดูจาก **magic bytes** (`sniff_image_type()` :547) ไม่ใช่ชื่อไฟล์ — เพราะรูปแนบแชตถูกแปลงเป็น JPEG ทุกไฟล์แล้วชื่ออาจลงท้าย .png
  - `safe_site_filename()` :579 flatten ชื่อเป็น basename เสมอ (`../evil.png` → `evil.png`) และห้ามชื่อ `index.html` ในลิสต์ไฟล์
- `DELETE /api/sites/<id>` (:3128) — ลบ row + `shutil.rmtree` ทั้งโฟลเดอร์ (ยังไม่มี UI ใช้ — เผื่อไว้ทำหน้าจัดการภายหลัง)
- นามสกุลที่รับ: `SITE_FILE_EXTS` (:106) = รูป (png/jpg/webp/gif/svg/ico) + css/js/json/txt/md/woff/woff2

**ฝั่งหน้าเว็บ (`index.html` — โค้ดใหม่อยู่แถว 976-1075)**

- `mdLite()` ตรวจ code block ที่ประกาศภาษา `html` → เติมปุ่ม **"🌐 เปิดเป็นหน้าเว็บ"** (`.site-btn` มุมซ้ายบนของ pre) ข้างปุ่มคัดลอก
- **auto-publish:** คำตอบที่จบ (`chunk.done`) แล้วมี code block เป็นเอกสาร HTML ครบชุด (`<!DOCTYPE html` หรือ `<html`) → เรียก `/api/sites` อัตโนมัติ แล้วโชว์ลิงก์ใต้โค้ด (`autoPublishPages()` :1067) — fragment/โค้ดครึ่ง ๆ ให้กดปุ่มเอง
- **จับคู่รูป:** `collectSiteFiles()` (:1004) ไล่ `src/href/poster/url()` ในโค้ดที่เป็นชื่อไฟล์เปล่า (ไม่ใช่ http/data/#) แล้วจับคู่กับรูปที่ผู้ใช้อัปโหลดในบทสนทนานั้น (เก็บใน `siteAssets` — รูปแรกดาวน์สเกล JPEG 1536px อยู่แล้ว, จับคู่ชื่อตรง/ตัดนามสกุล) → เซฟรูปไว้ในโฟลเดอร์เดียวกับ index.html ใช้**ชื่อตามที่โค้ดอ้าง** รูปจึงโหลดได้ทันที
- **ปุ่ม 🔗 บน chip รูปแนบ** (`renderAtts()`) — สร้าง site ที่มีแต่ไฟล์เดียว → ได้ลิงก์แกลเลอรี + copy ลิงก์ให้อัตโนมัติ + แปะบับเบิลลิงก์ในแชต
- **บอกชื่อไฟล์ให้โมเดลรู้:** ตอนส่งข้อความที่มีรูปแนบ ต่อท้าย content ด้วย `(แนบรูป: logo.png, ...)` เพื่อให้ HTML ที่โมเดลเขียนอ้างชื่อตรงกับที่อัปโหลด (จับคู่ตอน publish ได้)
- **แคชลิงก์:** fingerprint (FNV-1a 64-bit) ของโค้ด → url เก็บใน localStorage (`thani_site_links`, เก็บล่าสุด 300 รายการ) — เปิดแชตเก่าซ้ำ/กดปุ่มซ้ำจะเปิดหน้าเดิมแทนการสร้างซ้ำเปลืองโควตา

**การทดสอบที่ผ่านแล้ว (ในเครื่อง Windows):** `python -m unittest discover -s tests` = **136/136 ผ่าน** (เพิ่ม `SiteHttpTest` 9 เคส: publish+เสิร์ฟสาธารณะ, content-type ตาม magic bytes, แกลเลอรีอัตโนมัติ, key ผิด 404, traversal 404, index.html ลักลอบ, ชื่อไฟล์อันตราย, โควตาเต็น, ต้อง login สร้าง) + `node --check` กับ `<script>` ที่แกะออกจาก index.html ผ่าน

- ชื่อไฟล์ asset ของฟีเจอร์ sites ยอมรับเฉพาะ **อังกฤษ/ตัวเลข/จุด/ขีด** (`SITE_NAME_RE`) — รูปชื่อไทยจะ publish ไม่ได้และมี error message บอก (ออกแบบไว้กัน unicode trick ใน path)
- `/api/chat` ส่งภาพเป็น data URL ที่โดน downscale เป็น JPEG แล้วเสมอ — ฝั่ง sites จึงตรวจ MIME จาก magic bytes
- **heredoc ผ่านเทอร์มินัลแผงไม่ได้** — สคริปต์หลายบรรทัดต้อง base64 แล้ว `echo <b64> | base64 -d | python3 -` (เจอตอน deploy 2026-11-14)
- env ของบริการจริงอ่านจาก `/proc/$(pgrep -f draw_server.py)/environ` ได้ตรงกว่า `systemctl show` และห้ามพิมพ์ค่า secret ออกทาง log
- บัญชีทดสอบสคริปต์ E2E ใช้รหัสคงที่+ชื่อใหม่ทุกครั้ง — ถ้าสุ่มรหัสแล้วสคริปต์ตายก่อน บัญชีจะติดรหัสเก่าที่ไม่รู้ค่า (login 401 ตลอด)
