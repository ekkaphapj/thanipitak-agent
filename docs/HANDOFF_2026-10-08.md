5. **sync override.conf กลับ deploy/systemd ใน repo** ให้ตรงกับเซิร์ฟเวอร์
6. ของที่ผู้ใช้**ปฏิเสธ/ยังไม่ตัดสินใจ** อย่าทำเองโดยไม่ถาม: best-of-N สร้างเพลงหลายเวอร์ชัน (ปฏิเสธ — คงทีละเพลง), ตัวเลือก sampling ขั้นสูง (temperature/steps), การลบ qwen_3_4b.safetensors / qwen3-embedding

## วิธี deploy (ตามที่ใช้จริงล่าสุด)

1. แก้โค้ด → เทสต์ `python -m unittest discover -s tests` ให้ผ่านทั้งหมด → commit → `git push origin main`
2. เข้าเซิร์ฟเวอร์ผ่าน **แผง Ake Server** (`https://server.policeshield4.com`): login API ต้องมี header Origin/Referer → ได้ csrf+cookie → ใช้ `deploy_via_panel.mjs <csrf> <cookie> '<command>'` (รายละเอียดเต็มใน docs/DEPLOYMENT_2026-10-07_268fa54_mobile-ui.md)
3. บนเซิร์ฟเวอร์: `cd ~/thanipitak-agent && git pull origin main` → `python3 -m unittest discover -s tests` → `systemctl restart qwen-draw@ekkaphap` → เช็ค `is-active` + `curl 127.0.0.1:8190` + โดเมน
4. **รหัสผ่าน sudo/แผง: ขอจากผู้ใช้ในแชตเท่านั้น — ห้ามบันทึกลง repo** (ธรรมเนียมเดิม: อ้างเป็น `<sudo pw>` ในเอกสาร)
5. **กับดัก:** คำสั่งผ่านเทอร์มินัลแผงตัดที่ ~150 วิ — งานนาน (apt/pip/โหลดโมเดล) ต้อง `nohup ... >/tmp/x.log 2>&1 &` แล้ว poll; ส่งไฟล์ config ขึ้นด้วย base64 เลี่ยงปัญหา quoting

## กับดักที่เจอมาแล้ว (อย่าให้เจอซ้ำ)

- Ollama ลบโมเดลต้องใช้ HTTP method **DELETE** (`POST /api/delete` → 405)
- SearXNG: engine ที่ผ่าน `keep_only` ยังขึ้น `enabled=False` — aggregate ได้ 0 ผลจนกว่าจะ override `disabled: false` ต่อตัว; และผลว่างถูก cache — รอ TTL หรือ restart ก่อนสรุปว่าพัง
- โมเดล thinking (เช่น qwen3.5): เรียก Ollama โดยไม่ส่ง `think:false` → `response` ว่างเปล่า (โทเคนหมดใน thinking) — draw_server ส่ง `think:false` อยู่แล้วทุก path
- dropdown โมเดลในเว็บ cache 5 นาที — ติดตั้ง/ลบโมเดลแล้วต้องรอหรือ restart บริการ
- เครื่องที่ลงโมเดลจริง: เทสต์เคส "ไม่มีโมเดล" ต้อง mock `music_available` (ดู commit 8498792)
- multi-agent บนเซิร์ฟเวอร์เดียวกันเกิด conflict ได้ (บริการถูก stop ข้ามมือ) — ตรวจสถานะบริการก่อน/หลังทุกงาน (บทเรียนใน docs/DEPLOYMENT_2026-10-04_8498792.md)
